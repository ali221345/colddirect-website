# روش کار تیم ColdDirect

تاریخ شروع: ۷ اکتبر ۲۰۲۶. سایت زنده است؛ ادامهٔ کار Hermes، بدون بازسازی.

## مسئولیت‌ها
- هماهنگ‌کننده: خواندن حافظه و تاریخچه، انتخاب بالاترین P0/P1، تقسیم کار و گزارش فارسی.
- تحقیق: داده‌های واقعی Search Console و تحقیق رقیب برای مشتریان تعمیر تجاری لندن؛ متن کپی نمی‌شود.
- مهندسی: اصلاح کوچک در شاخهٔ جدا با تست متناسب و حفظ کارهای موجود.
- کنترل کیفیت: بررسی مستقلِ کد و نتیجهٔ سایت زنده؛ تفکیک شبیه‌سازی از آزمایش واقعی سرور.

## حلقهٔ اجرا
حافظه و کارهای باز → شواهد تازه → اصلاح محدود → تست → بررسی مستقل → درخواست تغییر GitHub → انتشار در محدودهٔ مجاز → کنترل زنده → ثبت نتیجه.
پیش از هر اصلاح، کارهای باز و آخرین main بررسی می‌شوند. کار تکراری ساخته نمی‌شود.
کارهای زمان‌بندی‌شدهٔ Hermes و GitHub حفظ می‌شوند. هماهنگ‌کننده از اجرای هم‌زمان نویسندگان روی یک فایل جلوگیری می‌کند.
وقتی مانع دسترسی یا تأیید وجود دارد، کار قابل بررسی تا مرحلهٔ مانع کامل و دلیل دقیق گزارش می‌شود.

## اجرای روزانه
پایش موجود ساعت ۹ لندن: بررسی ایندکس Google و بررسی فنی عمومی سایت. نتایج کامل در پوشه‌های reports ذخیره می‌شوند؛ اجرای ناقص جایگزین نتیجهٔ کامل نمی‌شود.
فقط مشکلات تازه، رفع‌شده، تغییر مهم یا اقدام لازم به فارسی گزارش می‌شود.
برای P0/P1 تأییدشده، هماهنگ‌کننده می‌تواند اصلاح جدا و درخواست تغییر آماده کند؛ این مجوز به معنای تغییر بی‌قید سایت زنده نیست.
main به Plesk انتشار خودکار دارد. [skip ci] این مسیر جداگانه را متوقف نمی‌کند. تغییر زیرساخت، DNS، قیمت، حذف گسترده یا تصمیم مسدودشدهٔ بررسی خودکار نیازمند تأیید لازم است.
پایش محلی نیازمند روشن‌بودن کامپیوتر، بازبودن Codex، دسترسی شبکه و فایل‌های موجود است. اولین اجرای زمان‌بندی‌شده باید بررسی شود.

## اولویت‌ها
1. P0 حلقهٔ صفحهٔ هزینهٔ تعمیر: اصلاح آماده؛ نتیجهٔ انتشار هنوز تأیید نشده.
2. P0 صفحهٔ brands با خطای 404: بررسی مقصد و علت، بدون حدس‌زدن انتقال به صفحهٔ اصلی.
3. P1 ناهماهنگی canonicalهای bare/slash: اصلاح با حفظ URLهای موفق.
4. P1 تطبیق مسیرهای انتشار و نویسندگان روزانه: پیشگیری از بازگشت خطا.
5. P1 کنترل اولین اجرای واقعی پایش روزانه و کارهای موجود.
6. P1 بررسی مسیر تماس و درخواست تعمیر روی موبایل، بدون ارسال درخواست آزمایشی واقعی.
7. P1 بهبود صفحهٔ Services بر اساس خدمات واقعی و دادهٔ جست‌وجو.
8. P1 سنجش کلیک، نمایش و صفحهٔ مقصد با بازه‌های زمانی قابل مقایسه.
9. P2 سنجش سرعت موبایل و Core Web Vitals پیش از بهینه‌سازی.
10. P2 تحقیق فرصت‌های تجاری و لینک داخلی؛ انتشار محدود بر اساس نیاز مشتری.

## اندازه‌گیری
ایندکس‌شدن، رتبه، کلیک و تماس چهار نتیجهٔ متفاوت‌اند. پذیرش درخواست ایندکس یا ثبت خط مبنا، رشد محسوب نمی‌شود.
قیمت، ضمانت، گواهی و مشخصات بدون منبع معتبر ساخته نمی‌شوند. Google Indexing API برای صفحهٔ معمول خدمات تعمیر اجرا نمی‌شود.
